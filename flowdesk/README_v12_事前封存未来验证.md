# FlowDesk v1.2 — 事前封存的未来订单流研究（原工程整合）

本版本直接以用户 FlowDesk v1.1 原工程为底座，保留 Moomoo OpenD 只读连接、原有网页、全美股当前股票池扫描、动态观察名单、多 Agent、完整分段录制、12 条固定订单流研究假设、组合资金/做空/成本/数据质量审计。**未接入交易下单 API、真实券商账户或任何自动交易。**

## 为什么新增这个模块

原 v1.1 的 60% 较早日期选模 / 2 天隔离 / 较晚日期观察，属于历史时间切分。由于程序员过去已看过旧行情和研究结果，这不是未碰过的独立测试。新模块 `trial_registry.py` 把一个未来时间窗口**在行情到来前**登记进本地哈希注册簿，并将未来采集每次运行绑定到预登记协议，填补研究中的因果证据缺口。

### 和过去不同的硬门槛

1. 必须在第一个研究日之前冻结试验。默认从下一个标准美股交易日开始，长度 60 个交易日；禁止回填今天或过去日期。标准节假日和提前收盘参照 `feed_guard.py`，不能替代交易所对临时闭市的认证。
2. 必须提前选择**一条主要研究规则**（默认 `follow-L1-H60`，只是任意固定对照，不是经验证盈利冠军），同时固定其他 11 条作为研究背景；正式试验只核算预选的一条主规则的影子账户表现，避免从 12 个事后挑赢家。
3. 冻结时记录工程根目录**全部 Python 源文件 SHA-256**、固定订单流假设、8/20/40 bp 额外往返成本假设、完整 60 个日期和一次性最终验收口径。动态股票池可随事先批准的扫描结果变化，但选股逻辑源代码变更将触发拒绝。
4. 冻结时拒绝有正在运行的采集器；后续本机启动实时 `Start.command` 会检查锁定代码与本地登记、将 `trialId` 和 `trialSealSha256` 写进每个原始录制的开始事件及最终元数据。不允许带封存试验启用 `--no-record`。
5. **试验期间实时看板隐藏每策略平均收益、最近影子退出的净收益**；`TrialStatus.command` / `/sealed-trial` 不输出中途盈亏。行情原始数据仍存在本机，使用者技术上能另行计算收益，因此本机“盲态”仅为软件纪律，**不能阻止主动偷看**。
6. 结束后才可一次性 `finalize`：检查每个运行是否被登记、是否有未归属试验的运行、是否有原始分段缺失/篡改、前瞻日志和原始盘口是否对应；按预先列出的美东交易日审计有效基准报价、健康监控与最长缺口。对**任何**缺失、重复、无效交易日均拒绝推进收益候选。
7. 即使全部日期有效，也只比较**预选单条主规则**的反事实长头寸、账户资金预算、真实可见盘口深度和 40bp 成本压力。未能确认平仓，整个统计拒绝推进；不把缺行情日默认为收益 0，但合格且无交易日可计为 0。
8. 结果无论正负，`tradeEnabled=false`、`profitCertified=false`：盘口报价穿价模拟不是实际下单、实盘成交或已验证可持续盈利，缺少第三方独立公证、交易所级时间戳和真实经纪商成交记录。

## Mac 具体操作

**第一步：** 备份旧工程及其 `recordings/`、`research/`、`output/`。解压 v1.2 并使用此版完整项目（不要只覆盖某一个 Python 文件）。`Start.command` 保持原启动路径；需要已登录的 Moomoo OpenD 和正确权限。任何收费行情均须在账户内自行授权；本软件不会下单或购买数据。

**第二步：** 在你准备连续观察未来完整交易日、并且**已经停止旧 `Start.command`** 后，双击新增的 `FreezeTrial.command`。默认从下一标准交易日开始未来 60 个交易日，只冻结一条固定初始假设。可先在终端查看规则：

```bash
cd /你的实际路径/FlowDesk
python3 -c 'from prospective import RULES; print("\\n".join(x["id"] for x in RULES))'
python3 trial_registry.py freeze --rule follow-L1-H60 --sessions 60
```

**重要：** 两种入口二选一即可，不要重复冻结。在做主规则决策前不得查看将用于验证的未来市场数据。默认 `follow-L1-H60` **不是**推荐买卖策略，只是事前冻结的探索性主假设。如果本地代码冻结后被修改，源代码完整性门禁会拒绝后续录制；正式试验期间请不要原地升级该文件夹。

**第三步：** 每个美股交易日保持 OpenD 和 `Start.command` 稳定连接、连续采集，避免机器休眠、磁盘写满与订阅失效。可运行 `AuditCoverage.command` 检查工程数据质量；不要查看正在进行的盈亏、重选规则或调整成本假设。

**第四步：** `TrialStatus.command` 在试验期间仅返回 `BLINDED_FUTURE_TEST_IN_PROGRESS`、日期与哈希；网页中也可点击“已封存未来试验状态”。

**第五步：** 试验最后一个交易日美东收盘后，再双击 `FinalizeTrial.command`。它只允许解封一次，结果保存在：

```text
research/sealed_trials/<trial-id>/final_report.json
research/sealed_trials/<trial-id>/final_report.sha256
```

结果包括全部预定日期（不是挑出的盈利日）、失败/缺失日期、40bp 成本后账户*报价模型*贡献、探索性五日区块自举区间、最差已闭合日与闭合模型最大回撤。没有真实成交的亏损尾部风险无法估计。`PROMISING_COUNTERFACTUAL_QUOTE_MODEL_ONLY` **不是交易许可，也不是经证明的 Alpha**。

## 排查命令

```bash
python3 -m unittest discover -s tests -q
python3 trial_registry.py status
python3 bridge.py --offline --no-record --no-browser
python3 audit_daily_coverage.py --recordings recordings
```

离线运行不会采集真实报价。`--offline` 专供自检。`AuditChronological.command` 仍是较早/较晚历史切分的探索报告；它**不能替代**本次事前封存。

## 验收和局限

- 共 170 项 Python 单元与对抗测试通过，包含 v1.1 原有 146 项和新增 24 项；其中未来盈利情景的测试数据是**人工合成**，不代表曾取得 60 个真实有效交易日。
- 原网页、HTTP 状态和只读 `sealed-trial` 路由已在隔离环境离线运行，JavaScript 已作语法检查。
- 当前项目内没有新取得的全市场连续日盘订单流数据；旧 64,420 条记录只覆盖两只股票、一个日盘交易日，并且没有 SPY 的完整日盘报价。这个旧样本**不可能**变成事前封存未来测试数据。真正未来试验在本机 `FreezeTrial.command` 执行后才成立。
- **本地哈希与本地机器时间都可以被有权限的人同时更改。** 因此这些证据主要用于发现意外修改、保持方法纪律，不构成独立监管审计或时间公证；真正机构级验证仍需独立存储/时间戳与券商实际成交回报。
- 当前任何模块都没有证明有稳定收益、没有最优保证、不建议在未验证情况下借贷或加杠杆。
