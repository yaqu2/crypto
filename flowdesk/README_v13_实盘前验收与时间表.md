# FlowDesk v1.3 — 实盘前验收（原工程升级）

**定位：这是原 FlowDesk v1.2 的只读研究升级，不是自动交易软件，也不是已找到盈利策略。** v1.2 的所有研究、扫描、前瞻录制与封存功能保留。新增 `live_readiness.py`、`paper_probe.py` 和两个 Mac 双击入口；结果可在原网页 `live-readiness` 与 `paper-probe` 查看。

## 什么时候可以投入真实资金？

截至 **2026-10-14**：**NO-GO**。要分清：

1. **现在可以做**：本机 OpenD 行情连接、全市场扫描、只读模拟账户发现、数据质量与前瞻研究。完全不需真实下单。
2. **下一阶段才考虑**：经单独审查的模拟账户订单/撤单生命周期测试（v1.3 本身**没有**下单模块）。Moomoo paper 订单状态不能代替交易所真实逐笔成交和手续费。
3. **极小资金真人批准的成交校准**：至少需要连续且完整的多日行情、提前冻结的未来策略取得正且稳健的报价模型结果、模拟账户全生命周期与独立风险限额测试，并落实正式券商的交易权限、最大亏损、熔断、断网撤单和人工确认；这是交易执行实验，不是稳定盈利证明。
4. **扩大本金/杠杆**：必须取得足够多的真实券商成交回报、收费、部分成交与取消记录，验证组合实际净值回撤、风险和交易容量。未通过不扩大；不保证任何日期。

假设在美东 **2026-10-15** 启动完整的 **60 个交易日**事前冻结实验，按现有标准 NYSE 交易日历，理论最后日期为 **2027-01-11（美东）**。这是**研究窗口结束时间，不是实盘授权时间**。断流、假日临时变动、代码变化等都可能使本轮试验失败，必须重新启动新一轮。它不包括此后的券商执行验证时间。

## Mac 实际操作

1. 完整解压到新目录，先备份旧工程及旧目录中的 `recordings/`、`research/`、`output/`。**不要只覆盖几个 `.py` 文件，也不要覆盖正在进行的冻结实验的代码**：既有封存的源代码哈希会失效。
2. 启动并登录本机 Moomoo OpenD；运行 `Start.command`，检查真实日盘订阅和 SPY 基准报价覆盖。`ScanMarket.command` 负责全市场宽扫描，不等于全市场同时订阅 L2。
3. 运行 `PaperAccountCheck.command`：调用 OpenD 的 `OpenSecTradeContext(TrdMarket.US).get_acc_list()`，**仅返回 SIMULATE 股票模拟账户的数量**；不读取账户余额，不显示账号，不下单、不撤单、不解锁真实账户。
4. 运行 `Readiness.command`：生成 `research/readiness/live_readiness.json`，在原网页点击“实盘前验收”。研究尚未完成时必然显示 `NO_GO_LIVE_REAL_MONEY`。
5. 若要审计一份**完整结束**的单次录制（而非未完成 ZIP 前缀），可在终端执行：

   ```bash
   python3 live_readiness.py --recording recordings/你的完整运行目录
   ```

   单次运行通常只有一天，**不能**用一天冒充 30 个交易日；正式未来试验的封存解封器会检查全部登记运行与预定交易日。
6. 开始新一轮正式未来实验，必须先运行 `FreezeTrial.command`，再启动 `Start.command`，坚持不提前窥视盈利结果。到期运行 `FinalizeTrial.command`，随后重新运行 `Readiness.command`。

## 实盘前验收程序会拒绝什么？

- 原始录制未结束、缺文件、数据篡改、报价长时间过期；
- 未事前冻结未来测试；测试仍在进行中提前看收益；没有一次性正式解封；
- 研究源码哈希改变、最终报告 SHA-256 不匹配、报告没有对应冻结协议；
- 未来试验结果不支持成本 40 bps 条件下探索性正收益，或有效日不足、未解决持仓；
- 无模拟账户、模拟账户检测过期；
- **即使前瞻报价模型结果漂亮，仍然缺真实成交回报、滑点和风险控制**：绝不直接激活真实下单。

## 重要技术边界

- 所有本地 JSON 和哈希都无法抵抗拥有完整文件写权限的人蓄意重写整个历史；需要异地只追加归档及第三方可信时间戳才可提高抗篡改能力。
- Moomoo OpenD 盘口快照不等于完整逐订单 MBO，也不等于全市场 SIP NBBO。
- Moomoo API 文档指出美股纸面交易可使用 `TrdEnv.SIMULATE`，但模拟账户不支持真实逐笔成交查询和准确费用核验。`paper_probe.py` **只发现账户**，未调用 `place_order`。
- `live_readiness.py` 不会自动授权任何资金，不提供 `TrdEnv.REAL` 下单功能。实盘部署需要独立的权限、风险、系统安全和合规审查。
- 统计模型在未来样本中取得正均值不保证未来持续盈利；实盘账户可能遭遇停牌、无流动性、价格跳变、融资券及税费问题。

## 代码/接口

| 入口 | 作用 |
|---|---|
| `PaperAccountCheck.command` | 只读检查是否发现 Moomoo 美股模拟账户；不会输出敏感账户信息 |
| `Readiness.command` | 生成明确的实盘前 NO-GO 审查清单 |
| `GET /.../paper-probe` | 展示已生成的只读账户发现诊断 JSON |
| `GET /.../live-readiness` | 展示已生成的实盘准入审计 JSON |
| `FreezeTrial.command` / `FinalizeTrial.command` | 原 v1.2 未来封存与一次性解封，不改变协议逻辑 |

## 系统当前研究结论

原 64,420 条采集记录是未结束的前缀，只有 **2 只股票、1 个常规交易日**的少量盘口事件，且 SPY 经过源时间检验的日盘报价分钟为 0。**旧数据不构成任何可认证净收益证据**。本轮测试验证程序不误授权交易，测试数量不是 Alpha 收益次数。
