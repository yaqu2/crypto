# FlowDesk v1.4 · 真实盘口因果与执行严检

**这是你此前上传的 FlowDesk v1.3 原工程继续开发的整合版，不是另起系统。** 保留原 `Start.command`、全市场扫描、多 Agent、订单流、哈希录制、组合审计、冻结未来实验、模拟账户只读检查和实盘前验收。不含 `place_order`、自动买卖或真实账户策略授权。

## 这次修复的具体缺陷

1. **全局门禁的时间来源**：过去 `Runtime.good_quotes` 保存本机接收时间，导致供应商本身滞后 15 秒的报价，在接收后又获得额外 20 秒的“新鲜期”。现在只保存经过检查的 `sourceAsOf`，使门禁真正按供应商报价源时间计龄。允许最多 2 秒可解释时钟超前，超过就拒绝。
2. **目标股票必须有自己的实时报价**：过去有时只看全局 SPY 通过和 `target.quote` 显示的报价；初始缓存也可能出现在该字段。新版每一次盘口影子研究都要求 SPY 和这只股票各自具有**已经被实时推送、经源时间审查、相对于盘口接收时间不超过 5 秒**的报价，且同一连接世代内有效。无实时推送、仅靠 `get_stock_quote` 初始快照、报价倒退等情形拒绝。
3. **展示不能误盖**：被研究引擎拒绝的旧/乱序报价，不再覆盖先前已接受的实时报价；无效盘口也不覆盖有效盘口，但仍会被送入实验门禁用于阻断与计数。
4. **影子名义金额**：如果一股价格已超过 1,000 美元实验名义规模，不再强制买入“一股”，而是明确取消该实验。仍然不能证明实际券商成交。
5. **重复触发**：固定 10 秒退出/取消后的同策略冷静期，阻止同一盘口状态反复制造大量高度相关样本。实验协议会保存该冷静期参数和新的代码指纹；旧版冻结实验不得拿新版本结果续接。
6. **新增独立原始日志配对审计**：`quote_pair_audit.py` 以原始回调的先后顺序复核“SPY 源报价 + 个股源报价 + 后续盘口”，不允许使用未来才收到的报价，也不允许把缓存补推当作实时证据。

## Mac 的实操顺序

先备份整个旧项目，**尤其是 `recordings/`、`research/`、`output/` 与 `watchlist.json`**。若有正在进行的 v1.3 封存试验，**不得替换该试验正在使用的代码**；新版本应放在另外的研究目录，待试验结束再切换。修改研究代码会改变 SHA-256 指纹，属于新实验，不应“接着算”旧样本。

1. 在 Mac 上安装并登录 Moomoo OpenD，监听地址保留本机 `127.0.0.1:11111`；禁止公开暴露端口。
2. `Start.command`：启动只读 FlowDesk，确认 SPY、目标个股订阅确实有**实时源报价**，而不只是 connected=True。
3. `ScanMarket.command`：获取当前全市场目录和批量快照；需要人工确认后才能在下次启动启用深度监控股票池。Moomoo 权限额度决定实际覆盖，快照不等于 L3/MBO。
4. 正常结束完整录制后运行 **`AuditQuotePair.command`**；它默认选择 `recordings/` 下最近一次保存的运行目录并生成 `research/latest_quote_pair_audit.json`。在网页“行情覆盖与候选选择审计”栏目打开“盘口与报价因果配对审计”。
5. 也可以执行 `AuditRecorder.command`、`AuditCoverage.command`、`AuditForward.command`、`AuditPortfolio.command`、`AuditAlpha.command` 等原入口。

### 对历史录制做只读诊断

原始未结束的 ZIP 导出不可认证为完整交易日，但允许做诊断：

```bash
python3 quote_pair_audit.py --recording /实际路径/events.jsonl --diagnose-prefix --out research/prefix_pair_audit.json
python3 research_study.py audit --events /实际路径/events.jsonl --out research/prefix_research_gate.json
python3 -m unittest discover -s tests -q
```

### 两层数据的边界

- **股票目录/批量报价**：寻找全市场候选和市场环境，不代表拥有全美股同时推送的 L2。
- **重点股票盘口快照 + 成交**：可以计算盘口压力、微价格与 OFI 代理，但不等于逐订单撤单记录、完整 NBBO 或真实可成交价格。现有影子收益依旧属于反事实报价模型，没有真实券商成交回报。

## 本轮已执行的验收

- 旧版基线 **192 项测试通过**；修复后 **223 项通过**（其中 31 项为新增的来源/冷静期/因果审计对抗测试）。它们证明软件逻辑，没有验证真实盈利。
- 对用户旧 64,420 条事件做两种独立只读审计：常规日盘仅 105 条盘口、2 只股票、1 个交易日；其中有有效的先行个股+SPY源时间证据的盘口 **0 条**，因为无 SPY 同步基准。状态 **NO-GO**。
- 新增 `quote_pair_audit.py` 的离线审计仅证明本地因果链，**不认证**数据供应商完整性、NBBO、券商成交、投资回报或未来 Alpha。

## 盈利前必须通过的关卡

1. 多交易日基准有效源报价和候选股票盘口覆盖；缺失/断流可定位。
2. 对一个事先封存的主要研究假设完成未来独立样本；在多个市场状态下费用、成交、尾部风险假设均可信。
3. 获取真实模拟下单或小规模券商成交回报，确定可用额度、滑点和部分成交（需要明确授权且使用独立受限系统）。目前本工程仍无自动下单接口。
4. 资金约束、借券、隔夜风险、熔断、审计全部通过。未经真实成交核验，不批准实盘或杠杆。

**即使代码成熟也可能没有可持续 Alpha；是否盈利只能由未来独立实际成交数据验证。**
