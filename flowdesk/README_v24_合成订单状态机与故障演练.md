# FlowDesk v2.4 — 合成订单状态机与极端故障演练

以 v2.3 原工程为基线。这次增加一套**纯离线、仅接收明确标记为合成事件的订单生命周期演练器**，不连接 Moomoo 交易接口、不发送委托、不读取账户、不假装从报价中产生真实成交回报。保留原实时行情信号、原市场扫描、原 A/B/C 快照与原组合报价压力研究。

## 已实现的订单状态和保护

- `PLACE`：只生成模拟订单意向（`PENDING_ACK`）。新买单预留 `数量×限价` 的模型资金；新卖单只允许卖出**已经在本次合成情景中模拟买到、且尚未被其他卖单锁定的股份**。单单上限 1000 美元，总模型占用上限 5000 美元，最多 5 个未结束模拟订单。
- `ACK`：仅**合成**接受消息；可以有行情/消息次序上的延迟。真实券商接受情况始终未知。
- `FILL`：只有显式提供 `source: SYNTHETIC_SCENARIO` 且数量、价格、时间合理的合成成交事件才影响模型仓位。**行情报价绝不自动构造成交。** 支持部分成交、累计数量和按成交成本核算的合成 PnL；默认附加 40 bps 往返成本压力。
- `CANCEL_REQUEST`：挂单进入 `CANCEL_PENDING`，**既不释放未成交买入的预留资金，也不释放卖出单锁定的股票**。如果撤单请求在途时合成成交到来，照样计入仓位。
- `CANCEL_ACK`：在已请求撤单后，才解除**未成交部分**的锁定；部分已成交股份继续占用资金。收到撤单成功后又发现成交，触发冲突错误，必须另行对账。
- `REJECT`：释放尚未成交部分；已经模拟成交的部分继续持有，不虚构归零。
- `DISCONNECT`：开启保守隔离，禁止继续下达新的模拟委托；原委托和仓位继续占用模型资金，直至取得独立对账证据（当前研究版无自动解除隔离的接口）。
- 故障检查：重复回报、乱序时间戳、未带时区的时间、零/负/NaN 报价、超量成交、越过限价、重复卖出预留、超资金上限和错误撤单均直接拒绝。

**重要：`REJECT`、`ACK`、`FILL`、`CANCEL_ACK` 都是人为编写的**合成事件，不能被解释为券商真实订单状态；本版本不估计真实订单排队位置、成交概率、冲击、券商手续费或真实净值。已显示报价与真实可执行 NBBO 之间的差距依然存在。

## 运行和检查

首次运行建议使用工程内置的**完全虚构的故障演练**：

```bash
cd /Users/quyang/Desktop/FlowDesk
bash StudyOrderLifecycle.command --demo
```

输出为 `output/rehearsals/order_lifecycle_report.json`（与真实 `output/market` 分开），网页“行情覆盖与候选选择审计”内有单独的只读报告入口。内置例子使用**虚构的** AAOI 与 NVDA 订单演练，演示：部分成交、撤单途中再次成交、撤单成功、卖出部分成交、拒单和断线；**这些不是这些股票曾经发生的真实成交**。

不附 `--demo` 或 `--scenario` 运行会正确输出 `NO_GO_NO_EXPLICIT_SYNTHETIC_SCENARIO`，且返回非零退出码。也可自己在本地准备明确合成 JSON：

```json
{
  "scenarioType":"EXPLICITLY_SYNTHETIC_ONLY",
  "events":[
    {"eventId":"e1", "at":"2026-10-14T13:30:00+00:00", "type":"PLACE", "source":"SYNTHETIC_SCENARIO", "orderId":"buy-1", "side":"BUY", "symbol":"US.AAOI", "qty":4, "limitPrice":100.0},
    {"eventId":"e2", "at":"2026-10-14T13:30:01+00:00", "type":"FILL", "source":"SYNTHETIC_SCENARIO", "orderId":"buy-1", "qty":2, "price":99.9}
  ]
}
```

运行 `bash StudyOrderLifecycle.command --scenario /path/to/synthetic.json`。

## 哪些成果能够证明，哪些不能

这次可以证明**状态机对设定场景的处理符合测试中的工程不变量**：取消请求不立即释放资金，部分成交不会被抹掉，断线后不开新单，不能超量或超限价计入模拟成交。但我们依然没有客户 Mac 上新的全市场行情归档或券商订单回报，**无法验证真实成交率、稳定 Alpha 或实盘收益**。

## 部署要求

只适用于未修改的 v2.3 完整工程，并且不处于封存未来实验中；有封存研究时请单独新建工程目录，保留旧记录。安全安装器在部署前检查原代码 SHA-256、补丁 SHA-256、冻结实验状态与是否存在运行中的本机行情采集进程。失败回滚并保留 `recordings/`、`research/`、`output/`；任何既有研究报告均不被覆盖。完整部署应在用户 Mac 上检查 OpenD 与实际行情资格；本合成执行演练不需要 OpenD。
