# FlowDesk v0.6：在原工程基础上建立可审计的前瞻净收益证据链

**研究目标**：全市场动态机会发现 → Moomoo 深度观察 → 订单流假设 → 未来报价执行敏感性 → 独立审计 → 小资金真实执行（未来，尚未支持）。

**当前结论：未证实 Alpha，禁止将观察结果视为自动交易授权。** v0.6 没有证券交易接口、账户访问、自动下单和资金划拨功能，不能承诺稳定盈利。

## 直接运行（Mac）

1. 备份旧 FlowDesk 文件夹。将本完整新文件夹解压到 Mac 本地硬盘，保持文件结构。
2. 登录本机 Moomoo OpenD，监听 `127.0.0.1:11111`。双击 **`Start.command`**（或运行 `bash Start.command`）。原始的扫描、盘口、K线、CVD、多 Agent 和浏览器看板保留。
3. 浏览器在原「多 Agent」下方增加「**前瞻影子实验**」面板。开盘时只有行情与录制健康条件同时成立才观察实验，不会提交订单。
4. 点击 `ScanMarket.command` 是**全市场目录 + 快照扫描**，不是全市场 L3 订单流采集。选择性配置 `watchlist.json` 中 1–60 只实时观察股票及少量深度股票，需要遵守真实订阅配额。
5. 开盘采集结束后按 `Control+C` 正常退出，使录制文件关闭、追加 SHA-256，并写入影子实验 `RUN_END`。
6. 双击 **`AuditForward.command`**，或运行：

```bash
python3 audit_forward_runs.py
# 输出 research/forward_audits/all_runs.json；审计所有 recordings/*/forward_shadow
```

每次打开的记录目录 `recordings/<run-id>/` 包含：

```text
recordings/<run-id>/
  events.jsonl                     原始行情/状态/订阅记录
  metadata.json                    本地录制状况、最终 eventsSha256
  forward_shadow/
    frozen_protocol.json           本次固定 12 条假设及交易成本口径
    protocol_seal.sha256           协议文件哈希
    shadow_events.jsonl            影子信号/入场/退出/取消/缺测，逐行串链哈希
```

**不要删除亏损或中断的录制**。`audit_forward_runs.py` 遍历每一个运行目录，不合格的记录也会出现在报告中。SHA-256 只能检测无意改动，不能抵抗删除整份录制/恶意重写所有文件；进一步独立审计需要远端不可变备份。

## 12 组严格固定、不许事后优化的前瞻假设

- 订单簿 1 档 / 5 档数量不平衡，0.35 绝对阈值：2 档位 × 2 时间跨度 × 延续/反转 = 8 种。
- **L1 OFI 代理变化**：相邻不超过 5 秒的真实新盘口快照计算，绝对阈值 0.30：2 时间跨度 × 延续/反转 = 4 种。它不能识别真实逐订单取消/成交原因，只是可见报价量变化的供需代理。
- 两个持仓观察周期：60 和 300 秒。
- 信号出现之后必须**至少等待 2 秒**，仅在 2–15 秒出现后续合格盘口才允许计算模型入场；持有指定周期后，只有 15 秒容忍窗口内有后续盘口才给模型退出。
- 模型多头**买入按未来盘口卖一、卖出按未来盘口买一**；假想做空**开仓按未来买一、平仓按未来卖一**；做空不包含借券费与可借股证明，不能用作真实空头收益。
- 在已跨买卖价差的基础上，分别额外扣除 **8、20、40 bps 的假定往返费用/延迟/滑点**。它们不是实测佣金，必须用真实回报进一步校准。注：40 bps=0.4%。
- 任一盘口异常、报价时间过旧、基准断流、OpenD 连接异常、写盘溢出、缓存快照、跨日期、交易日不明或录制异常时不产生合格结果；已开始却无法完成的机会记为 `CENSORED` 而非盈利。

模拟收益的数学定义（以价格比例计）为：

`net_shadow_bps = direction × (exit_cross_quote / entry_cross_quote − 1) × 10000 − additional_cost_bps`

它不是账户损益、可成交收益，也无法证明赚钱。特别是 Moomoo 返回的是覆盖受权限限制的盘口，不能假装为全市场合并 NBBO，不能得知真实排队或撤单生命周期。Moomoo 文档对盘口服务端时间还提示部分字段仅支持港股；本程序严格使用**本机回调接收时间**作为事件先后依据，而不是虚称交易所交易时间。

## 独立审计包括什么

`forward_report.py` 单个运行：

```bash
python3 forward_report.py --run-dir "recordings/某次运行编号/forward_shadow"
```

检查：协议冻结、源文件哈希、逐行 SHA-256 串链、每条入场必须晚于信号 2–15 秒、每条退出必须晚于入场 60 或 300 秒、计算结果必须含跨价差和 8/20/40bps 额外成本、不可凭空造出孤儿成交；任何无法完成的记录不计算 PnL。

`source_crosscheck.py` 让影子日志里的每笔信号/入场/退出价格和接收时刻，必须与原始 `events.jsonl` 中的同一只股票盘口回调一致。`audit_forward_runs.py` 强制这种比对，校验录制最终 SHA-256（若存在），并扫描所有运行目录。

当独立日期达到至少 20 个、覆盖至少 10 只出现模型退出的股票、至少 200 个合格报价模型退出时，可以开始形成更稳定的前瞻**研究样本**。这不是充分统计功效标准，更不是实盘授权标准：盘中簇相关、跨股票共同风险、幸存者偏差、Moomoo 行情覆盖、市场冲击和真实成交仍需额外处理。即使这些门槛满足，报告 `verdict` 仍为 `NO_GO_LIVE_TRADING`。

## 原工程保留和新文件

原运行路径：`bridge.py` → `runtime.py` → `intelligence.py` / `flow.py` / `multiagent.py` → `dashboard.html`，以及录制 `recorder.py`。新增：

- `prospective.py`：固定 12 组前瞻假设、延迟报价模型、失效机会记录和带哈希串链的异步证据日志。
- `forward_report.py`：单次实验因果和成本一致性检查。
- `source_crosscheck.py`：与原始 Moomoo 回调逐笔核对。
- `audit_forward_runs.py` / `AuditForward.command`：所有运行集合审计，避免挑选有利运行。
- `tests/test_forward_research.py`：未来入场、缺失退出、成本、篡改、OFI 代理、失效门禁、运行集合反择优与原 `runtime.py` 接入测试。

## 下一步怎样争取可持续盈利

1. **首先修复日盘数据连续性**，重点检查 OpenD 账号权限、实际订阅、SPY 报价源时钟、回调流、落盘和 CPU/磁盘状态。若信号稀疏，研究时间自然会延长。
2. **扩展可追溯全市场候选**，重点保持当前上市股票目录和历史点时股票池分开，遵守订阅与流量额度；动态重点股票盘口应有跨行业样本和明确的入选前规则。
3. **预注册研究并积累前瞻数据**。不能在同一测试集上反复挑「赢的策略」，要以交易日为聚类单位做误差估计、考虑多重比较，并在不同市场环境重复验证。
4. **券商纸面成交及小额真实成交对账**。用真实撮合回报校准滑点、成交概率、券商费用、部分成交和反向选择；缺少真实订单回报，无论模型报价盈利多少，始终不能认定能持续赚钱。
5. **资金控制**：在正净收益与风险证据未独立确认前，不开实盘自动策略、不加杠杆、不宣称年化收益。

最重要的承诺：**研究可以失败，证据不能造假。**
