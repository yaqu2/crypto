# FlowDesk v0.5 · 原工程多 Agent 交叉验证与订单流研究

**这是直接修改用户上传的 FlowDesk v0.4 原工程的完整可运行副本**，保留原 `bridge.py`、`runtime.py`、`intelligence.py`、`flow.py`、`recorder.py`、`dashboard.html`、`Start.command`、`watchlist.json` 等主要功能。在已整合的行情质量守卫和 Moomoo 全市场快照程序基础上升级。不包含券商交易 API、自动下单、账户读取、杠杆或期权交易执行。

## 三个可执行入口（Mac）

**1. 实时研究。** 确认 OpenD 已登录并在 Mac 本机 `127.0.0.1:11111` 监听。双击 `Start.command`，浏览器中新增 **多 Agent 交叉审查**。原观察池仍为 14 只。未安装的 SDK 会安装到本项目 `.venv`。实时版无法由 ChatGPT 隔离环境直接连接你 Mac 的 OpenD。用户应先备份原文件夹，解压本压缩包为新文件夹运行。

**2. 全市场扫描。** 双击 `ScanMarket.command`。依次运行现有的 `market_scan.py`、新 `universe_agents.py` 和 `prepare_watchlist.py`：
- `get_stock_basicinfo()` 获取**当前**美股股票目录，不是历史点时股票池；
- `get_market_snapshot()` 按每批最多 400 个代码做一次快照；权限/订阅限制可能造成拒绝；
- 对股票目录和快照原文件做 SHA-256 一致性复核，验证是否缺失、过期、重复；
- 若达到严格完整覆盖门槛，按**单次截面异常变化幅度与成交额**排序，最多保留 60 个「观察优先级」，这是筛查待研究标的，并**非**收益预测、买入评级或历史订单流；
- 输出 `output/market/agent_candidates.json` 和 `proposed_watchlist.json`。后者最多建议 36 只普通订阅、5 只深度订阅，但**不会自动覆盖 `watchlist.json` 或改变已运行的 OpenD 订阅**。变更观察池需人工审阅配额、权限、流动性、代码类型和行业分组。
- 报告未达到认证门槛（例如 400 只权限额度、缺行情或不在美股交易时段）时，`NO_GO`，不会生成正式的全市场候选列表；可以在终端用 `bash ScanMarket.command --max-symbols 40` 测试权限，但**这不代表全市场**。

**3. 严格订单流离线审计。** 双击 `AuditResearch.command`，自动审计最近一次录制的 `events.jsonl`；或者终端运行：

```bash
cd /你的路径/FlowDesk
.venv/bin/python research_study.py audit --events /你的路径/events.jsonl
```

只有当至少 **35 个有常规时段有效盘口的独立交易日**和至少 **20 只实际覆盖个股**出现时，才开放冻结研究准备。这些阈值是研究流程最低门槛，不表示统计功效已足够。正式冻结是**两步走**：

```bash
.venv/bin/python research_study.py prepare --events /你的路径/events.jsonl --out research/experiment_001
# 研究方案和原始数据SHA-256冻结，并在全程不查看测试集的前提下做好实验登记
.venv/bin/python research_study.py finalize --events /你的路径/events.jsonl --out research/experiment_001
# 一次性测试未来日期；此文件夹不能二次揭盲
```

现在只有预设的 8 种研究性订单簿假设：1档/5档盘口失衡 × 60秒/300秒 × 延续/反转。盘口源时钟未独立核实，买卖盘成交只是**跨报价的纸面成本敏感性**；模拟还假设 **8 bps** 额外往返费用和延迟损耗（非真实券商实测），入场使用信号发生 **2–15 秒后**可观测的盘口，且模拟不能证明填单。不同标的价格水平和波动可能导致成本更大。历史验证中使用按日固定 70/30 时间切分，测试日期不参与规则选择；看过测试后不得再在同一研究中调整参数。简单单侧近似统计检验采用 Holm 家族错误率修正（8 个假设）；每日簇均值仍可能有序列和跨股票相关，**不能称为精确显著性认证或稳健 Alpha**。必须继续多市场环境、真实订单成交、样本外前瞻纸面交易、市场冲击/滑点和幸存者偏差独立审核。

## 八个 Agent：真正职责分开、结论相互独立，但不是八个已部署的大模型

| 审查者 | 输入/权限 | 允许的结论 |
|---|---|---|
| 行情完整性 | OpenD 状态、源时间、接收质量 | 旧报价或连接异常时否决 |
| 市场范围 | 独立的全市场快照覆盖报告 | 缺失/过期/不完整时拒绝全市场论断 |
| 盘口微观结构 | 多档深度、最优买卖价、接收时间 | 只观察不平衡、微价格及点差；不可确认撤单动机 |
| 成交方向 | 当前会话的有效逐笔、方向分类 | 只给有覆盖限制的交易压力观察，不是全场所准确 CVD |
| 跨标的背景 | 同时间窗基准和同行 | 拒绝把未经核验的相关变化推成因果 |
| 统计反证 | 未来样本独立测试及预注册档案 | 没有验证净收益时硬否决 |
| 执行成本 | 可见买卖价差与明确的额外费用假设 | 展示跨价差成本门槛，不宣称真实成交 |
| 组合风控 | 风险预算、持仓与真实成交数据（尚不可用） | 无独立验收与风险约束时硬否决实盘 |

这些是可复现的**规则式角色审查器**（模块 `multiagent.py`），并没有接入八个 LLM API；系统不会无中生有生成新闻原因、对冲基金持仓或保证盈利。多个审查角色看到的是同一轮只读数据快照，不能各自制造新数据。

## 本轮实际验收

- 原工程 28 项 + 新增 17 项，合计 **45 项自动化测试通过**；它们测试的是代码和保护机制，不是 45 次净收益实验。
- Node JavaScript `--check` 通过；离线 HTTP 启动检测，网页 HTTP 200、状态 HTTP 200、没扫描时两个缺失报告 HTTP 404，报告包含 8 审查角色且 `liveOrdersEnabled=false`。
- 对提供的 64,420 条 `events.jsonl` 真实录制执行 `research_study.py audit`，结果 `NO_GO_INDEPENDENT_SAMPLE`：50,588 条推送盘口事件，常规时段 105 条，覆盖 2 只股票、1 个独立常规交易日。审计见项目上一级 `真实事件_研究门禁.json`（完整压缩包的 `research/真实事件_研究门禁.json` 副本）。
- **未连接用户 Mac OpenD、未获取新全市场盘口数据、未进行真实券商执行、未证明盈利或最佳策略。**

## 研究质量边界和安全

- 规则中任何展示型 `OBSERVATION_ONLY` **都不是**交易信号。`qualifiedForProfitClaim=false`，`tradeEnabled=false`。
- Moomoo 快照及报价不能冒充交易所完整 MBO；当源时钟为空，盘口只表示「本机收到」，不得断言撤销事件、真实队列位置或可成交的整档流动性。
- 当前股票目录有幸存者偏差，不是历史点时股票池；全市场快照的收益、成交额排序并非未来短线收益预测。
- `plan_seal.sha256` 和源文件哈希用于检测无意修改，不是抗恶意攻击的公证或远端不可变存储。正式研究建议将原始录制和预注册方案单独保存并由外部审计。
- 默认不加杠杆、不下单、不提交 API 密钥；停止研究台不会继续采集或后台自动替你交易。

**最大化真实收益的先决条件，是先有可验证、可执行、跨股票和跨交易日的订单流 Alpha。软件通过测试并不等于发现 Alpha。**
