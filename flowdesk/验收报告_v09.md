# FlowDesk v0.9 · 本轮独立工程验收（2026-10-14）

## 工作对象

基于用户提供的 FlowDesk v0.4 源码、以及此前 v0.8 完整工程原地升级；不是重新建立独立系统。保留 OpenD 订阅、全市场当前股票目录扫描、多 Agent 分工、研究前瞻实验、模拟资金约束与风控。**没有实盘订单接口。**

## 发现并处理的高优先级问题

1. **长期连续采集会触发旧版 256 MiB 全运行硬上限**，阻断研究数据积累。新版本默认 64 MiB/段、8 GiB 全运行上限，容量超限仍将录制标记为失败，不允许假装连续。
2. **旧版完整性审计只核验 `events.jsonl`**。新版本逐段验证 SHA-256、文件大小、JSON 行完整、事件数、严格连续序号和 runId；缺失任何中间分段、存在未登记分段，整次原始录制变成 NO-GO。
3. **旧导出可作为完整录制误判**。新版严格区分 `closed:false` 前缀快照和 `closed:true` 正常结束的录制；前瞻收益来源校验拒绝使用未关闭的前缀伪装完整录制。
4. **网页导出过大可能造成内存激增**。对原始大小 >256 MiB 的浏览器 ZIP 导出拒绝服务，要求复制本机整个录制文件夹，原始数据保留不删。
5. **加入全运行完整性审计**：`audit_recordings.py` 与 `AuditRecorder.command` 检查 run_inventory 中登记的所有运行和孤儿目录，而不是事后只看交易表现好的录制。

## 用户旧数据的独立实测

- 旧原始导出 `events.jsonl` 共 **64,420 条 JSON 行，145,918,509 字节**；SHA-256 与 `metadata.json` 中的 `681248ac2b8a2cc49954008ed44b40808c9a6a3a561523181a5e218475cd7b5c` 一致；全部顺序号连续。
- 但旧元数据标明 `closed:false`、`exportType: prefix snapshot; recording continues`。故验收结果为 **PASS_LOCAL_PREFIX_BYTE_INTEGRITY_ONLY**，并非全天数据完整、供应商推送连续，更不是订单流盈利证明。
- 此前对该日志的日盘审查只有 2 只股票、1 个独立常规交易日、105 条常规时段盘口推送。旧数据不能认证全市场策略盈利，`NO-GO` 不变。
